# nockchain-go

A small, dependency-free Go library for Nockchain V1 receiving addresses and
wallet derivation. The Go package name is `nockchain`.

```sh
go get github.com/yapishu/nockchain-go
```

For this private repository, configure Git authentication and include
`github.com/yapishu/nockchain-go` in `GOPRIVATE`. Go 1.23 or newer is required.

## Scope

- Cheetah public keys over the Goldilocks extension field.
- V1 SLIP-10 master, hardened private, and non-hardened public/private derivation.
- Strict `zpub` and `zprv` parsing and serialization.
- Immutable based nouns with atoms below `2^64 - 2^32 + 1`, bounded traversal,
  and shape-preserving TIP5 noun hashing.
- TIP5 word hashing, public-key hashes, and V1 single-signature PKH lock roots.
- Exact conversion between NOCK and nicks (`1 NOCK = 65,536 nicks`).

Transaction construction, signing, submission, and blockchain verification are
outside this package's scope. Base ERC-20 NOCK uses **16 decimal places**; its
base units are different from native Nockchain nicks.

## Receive using a public extended key

```go
package main

import (
    "fmt"
    "log"
    "os"

    nockchain "github.com/yapishu/nockchain-go"
)

func main() {
    account, err := nockchain.ParsePublicKey(os.Getenv("NOCKCHAIN_ZPUB"))
    if err != nil { log.Fatal(err) }

    // Reserve this index durably before exposing its address.
    child, err := account.Child(0)
    if err != nil { log.Fatal(err) }
    address, err := child.Address()
    if err != nil { log.Fatal(err) }
    lock, err := child.LockAddress()
    if err != nil { log.Fatal(err) }
    fmt.Println("Send to:", address)
    fmt.Println("Index by lock root:", lock)
}
```

`Address` returns the V1 public-key hash accepted by sending wallets.
`LockAddress` returns the exact V1 single-signature lock root used for indexed
payment lookup, including semi-anonymous outputs. Neither address proves that
a payment exists; the application verifies the matching output and chain depth.

Give each application a dedicated receiving branch. Keep the spending wallet's
derivation path and backup, persist allocated indices, never reuse them, and
scan the corresponding children during recovery. An extended public key reveals
all non-hardened descendants and is privacy-sensitive.

## Offline wallet operations

`Generate` uses `crypto/rand`. `Master` accepts a 64-byte seed, including a seed
produced by BIP39 tooling. `Derive("m/44'/0'/0'/9000")` follows a path relative to
the supplied key. `Zprv` explicitly exports recovery material; `Zpub` exports
the public branch. `Public` strips private material from the returned key.

The arithmetic is **variable-time**. Run private-key operations offline, outside
request handlers and hostile shared execution environments. The online checkout
integration uses `ParsePublicKey` and public child derivation only. The library
does not implement transaction signing or claim a cryptographic audit. See
[SECURITY.md](SECURITY.md) for its security boundaries.

## Validation

```sh
go test -race ./...
go vet ./...
go test -run '^$' -fuzz FuzzParseExtendedKey -fuzztime 10s
go test -run '^$' -fuzz FuzzParseDigest -fuzztime 10s
```

The checked-in corpus has 35 deterministic wallet vectors, 13 TIP5 word vectors,
and seven based-noun vectors
generated by the Rust references. Tests compare private scalars, chain codes,
serialized public keys, addresses, lock roots, and both extended-key formats.
They also check public/private child agreement, parser rejection, exact amount
conversion, and diagnostic redaction. The corpus uses public test seeds only;
**never send funds to its addresses**.

Reference versions:

- [SWPSCO/tx-types](https://github.com/SWPSCO/tx-types), commit
  `5f9ab2b38f1685a908f19a0e8f18e7845b3e7f35`: no-std Cheetah derivation and TIP5.
- `siger-esp`, commit `d62110560dd005827ae8a46126c9841c86db0d6a`:
  `nockster-core` V1 public-key hashes and lock roots.

Regenerate the corpus from those local checkouts with:

```sh
python3 testdata/reference-generator/generate.py /path/to/tx-types /path/to/siger-esp
```

The reference generator requires Rust. Normal Go builds and tests require only
the Go toolchain and the checked-in fixtures.
